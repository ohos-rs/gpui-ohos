# OHOS 适配优化交付核对（2026-10-07）

核对版本：gpui-ohos `d9b2f1a`、openharmony-ability `2a5d247c`、NearSend `3fc7a78`。本文整理现有实现和验证结果，没有新增运行时代码。NearSend 的 22 个适配层源文件与 gpui-ohos 对应版本逐字节一致；Ability 锁定 `richerfu/openharmony-ability` 的 `feat/pr82-nearsend-integration` 分支及上述提交。

**结论：已确认的四项审计问题、后续输入帧调度问题，以及下面列出的性能优化均已实现。审计中的系统能力替换建议并非全部采用；UI 唤醒的入队结果/session 加固仍未完成，不能笼统宣称全部建议均已实现。**

## 已实现

| 优化或修复 | 实现与验证 |
| --- | --- |
| 复用后台线程 | 复用 worker 和 GPUI 优先级队列；空闲等待，多余线程空闲后退出。父任务同步等待子任务以及外部任务推进均有回归覆盖。 |
| 避免 CPU 繁忙导致盲目扩容 | 无出队只触发检查；通过工作线程持有的 procfs 文件读取系统 R/S/D 状态。phone、2in1 应用进程各 64 个 CPU 任务保持基础/峰值/线程数 4/4/4；16 对阻塞父子任务完成。内核状态读取失败时优先保障任务推进，不保证该异常路径的 CPU 并发优化。 |
| 合并 UI 唤醒与前台任务分批 | 复用接收器、合并 N-API 唤醒，每轮按 2 ms 或 64 个任务分批，剩余工作再次唤醒处理；任务及销毁保持所属 UI 线程。计时器显式唤醒，取消空闲轮询。入队失败边界见下节。 |
| 按需系统 VSync | 静态/隐藏窗口停止无效帧工作；健康 NativeVSync 关闭冗余 XComponent 持续回调，失败恢复系统 Continuous 帧源。生命周期代次隔离旧回调。故障注入、前后台和多窗口验证通过。 |
| 遵循系统主队列交付绘制 | 原始输入与 Pan 回调立即交付并返回；NativeVSync 待绘制帧仅在 N-API 主队列 `UserEvent` 中消费。消除在同批输入之间执行绘制的适配层路径。 |
| 输入路由与数据复用 | 按窗口 ID 索引直接路由、借用输入事件，减少全窗口扫描和克隆。主窗口及 3 个子窗口输入、关闭、重开验证通过。 |
| GPU 资源复用 | 按设备/上下文缓存兼容 shader、layout、pipeline；窗口的 buffer、uniform、surface 保持独立。缓存变体回归与多窗口验证覆盖。 |
| 截图转换 | 逐行复制/转换，减少整帧清零和重复扫描；保留 RGBA/RGBX/BGRA/BGRX 支持，生产转换模块回归通过。 |
| native 资源销毁顺序 | Ability 先释放手势、回调与渲染消费者，再释放 ArkUI RootNode；已覆盖子窗口关闭、重开。 |
| Surface 创建不受帧注册失败阻断 | 先发布有效 SurfaceCreate，再协调帧源；请求状态与成功应用状态分开，失败可重试，销毁使应用状态失效。移除适配层重复缓存；首次两次注册失败与 RequestFrame 失败组合验证通过。 |
| Pan 跨会话状态清理 | 每次 Start 重置累计基线并立即交付已有位移；Cancel 缺少原始指针时仍收尾，Surface 变化清理状态。首次 -12 设备像素短拖在按住期间已显示；缺失终止序列由生产状态回归覆盖。 |
| viewport 发布 | 以已交付 GPUI 的有效 size/scale 去重，Surface、键盘、配置变化按需发布；修正尺寸换算，补全初始避让区 windowId。特定重建事件顺序有生产模块回归，设备覆盖实际 resize/重开。 |
| OHOS 专用 Ability | 移除非 OHOS 实现及 target_env 等平台判断，保留 OHOS desktop/mobile 设备类别。OHOS 三架构检查通过。 |
| 代码整理 | 清理 22 条既有 Clippy 错误；窗口构造参数归入上下文，字体名称替换减少一次分配。整库 OHOS arm64 all-features 严格 Clippy 通过。 |

GPUI 核心仍锁定原始 `f45c7c22d0c04fb12527e71bbbee1dc6bdbdee0a`。本轮框架优化保持现有动画帧率、滚动、控件捕获、IME、多窗口、渲染质量和截图格式；没有新增限制这些能力的开关或阈值。`requested`、`pending` 及生命周期代次分别表达不同事实，不应仅为减少标志位而合并。

## 未采用或仍未完成的建议

| 项目 | 当前状态与原因 |
| --- | --- |
| FFRT 替换执行器、映射系统 QoS | 原型已评估，未进入交付。在两端原生和应用进程中，所测 thread-mode 配置下 16 个同步等待父任务仅 4 个启动，12 秒内 0 完成。保留复用线程及 GPUI 优先级队列，以保持阻塞任务推进能力；此结果不代表全部 FFRT 配置。 |
| ArkUI Tap/LongPress 全面替换 | 未实施。当前 Pan 已使用系统识别、位移和速度；点击/双击兼容、控件捕获以及单次长按定时器保留。完整切换还需要证明全部输入语义对齐。 |
| 系统 Scroll/Animator 完全接管惯性 | 未实施。Pan End 不持续提供位移；当前每窗保留单一惯性曲线，由 NativeVSync 驱动。尚无已验证、覆盖现有自绘滚动语义的系统替代实现。 |
| UI 唤醒入队结果与 session 所有权 | **尚未完成的可靠性加固项。** Ability `OpenHarmonyWaker::wake()` 仍返回 `()`，未向调用方传递 TSFN 入队状态，并读取全局当前 WAKER；适配层无法据此区分合并请求与入队失败。现有合并和关闭处理已实现，但不能作为此项完成的证据；本轮未观测到该边界导致的设备故障。 |
| 模拟器 GLES present 内部阻塞 | 已做同包重启、旧包复测对照，未修改系统驱动。重启后的改善不计入适配层代码收益。 |
